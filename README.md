# 珂拉课程表 · 一键导入扩展

在教务系统的课表页点一下，就把课表整理进珂拉课程表。用户不用复制粘贴任何东西。

## 装到浏览器

1. 打开 Chrome，地址栏输入 `chrome://extensions`
2. 打开右上角的「开发者模式」
3. 点「加载已解压的扩展程序」，选中这个文件夹

装好后，工具栏上会出现一个粉色图标。

## 用户怎么用

1. 先在 [card.clarkhub.cn](https://card.clarkhub.cn) 登录
2. 打开学校教务系统，点到「课表」或「我的课表」页面
3. 点工具栏上的扩展图标，再点「导入现在这一页」
4. 读完会显示读到几门课，点「去课表看看」就跳过去了

## 装好之后怎么看它有没有生效

回到珂拉课程表的导入页刷新一下。识别到扩展时，标题会变成
「扩展装好了，可以开始导入」；没识别到则显示下载与安装步骤。

判断方式是扩展在珂拉页面留了一个隐藏元素，页面查得到就说明装了。

## 一个容易踩的坑：教务系统必须是普通标签页

从站点上用 `window.open` 指定宽高打开的窗口，**没有地址栏和工具栏**，
用户在里面找不到扩展图标，一键导入就没法用。

导入页现在改成用普通标签页打开教务系统，扩展图标才在。
如果将来又有人想把它改回"漂亮的弹窗"，记得这一条。

工具栏上没看到图标时，点地址栏右边的拼图图标，把珂拉课程表固定出来。

| 学校 | 教务系统 |
| --- | --- |
| 金陵科技学院 | jwxt.jit.edu.cn |
| 吉林大学 | iedu.jlu.edu.cn |

新增学校要改两处：`schools.js` 里加一条，`manifest.json` 的
`host_permissions` 与 `content_scripts.matches` 里加对应域名。

## 它是怎么工作的

扩展**不解析课表，也不判断课表在哪**。

早先的版本会去找 `#Table1`、`.Nsb_r_list` 之类的容器，找不到就告诉用户
「这一页没找到课表」——可用户明明已经打开了课表页。方向错了：
各校模板的差异是后端的责任，解析器本来就在那边，扩展再猜一遍
只是多一层会出错的假设。

现在它只做一件事：把用户眼前这一页的 HTML（`document.documentElement.outerHTML`）
原样 `POST` 到 `/api/v1/imports/courses/html`，后端用 jsoup 解析整页，
自己去找课表那张表（如 JIT 用的是 `table#Table6`）。

好处是新增学校时**扩展不用改**——只要那所学校的域名在
`host_permissions` 里，剩下的全在后端。

## 文件

| 文件 | 作用 |
| --- | --- |
| `manifest.json` | 扩展声明、权限、支持域名 |
| `schools.js` | 学校清单与域名匹配 |
| `content.js` | 在教务系统页面里定位并取出课表 HTML |
| `bridge.js` | 在珂拉页面留标记，让导入页知道扩展已装 |
| `popup.html` / `popup.js` / `popup.css` | 点击图标后的界面与流程 |
| `icons/` | 扩展图标（粉底白线，表示课表） |

## 权限说明

- `activeTab` + `scripting`：只在用户点图标时读取当前页
- `host_permissions`：只列了上述两所学校的教务系统域名和珂拉课程表自己的域名
- `storage`：留给后续记住用户上次的选择，当前版本未使用

扩展不读取、不保存学校的登录密码。课表 HTML 只用于这一次导入。
